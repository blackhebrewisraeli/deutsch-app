# Phase 1.4 — Pack-Owned Grammar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move German grammar values (articles, auxiliaries, person keys, verb-display labels, CEFR scale) behind `pack.grammar`, so the engine's lexicon contract stops rejecting any non-German pack.

**Architecture:** The German pack gains a `grammar` block in its own module, mirroring how `theme.js` / `decks.js` / `lexicon.js` are already split out. `validateLanguagePack` enforces its shape. Then `formatVerb` and `validateLexiconEntry` take grammar as an explicit argument, and the `ARTICLES` / `CEFR` constants are deleted. The lexicon's field names and its 2.3 MB of shipped data are untouched.

**Tech Stack:** React 18, Vite 5, Vitest + React Testing Library. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-14-phase-1.4-pack-grammar-design.md`

## Global Constraints

- **This phase changes test files, and that is expected.** Phases 1.2 and 1.3 each held a "no test file changes" gate because both were pure refactors behind unchanged signatures. Here the signatures change, so churn across 21 `validateLexiconEntry` call sites and 10 `formatVerb` ones is inherent. **The narrower gate still applies: no component test may change** (`VocabTab.test.jsx` and friends). The vocab card's rendered output is identical.
- **No defaults on the new parameters.** `formatVerb(verb, grammar)` and `validateLexiconEntry(entry, { grammar, cefrLevels })` both require the new argument. Defaulting to `activePack` would drag the pack registry into pure modules.
- **Do not touch the lexicon data or the importer's logic.** `public/lexicon/chunk-*.json` and `scripts/import-lexicon/*.js` (other than `mapEntry.test.js`) stay as they are. Renaming schema fields is explicitly out of scope.
- **Tests use `globals: false`** — every test file must `import { describe, it, expect } from 'vitest'`.
- **Never bypass `.husky/pre-commit`** (`lint-staged` + full `npm test`). `--no-verify` is forbidden.
- **Branch from up-to-date `main`; land via a non-draft PR targeting `main`.** CI only runs on PRs targeting `main`.

## Three facts that will confuse you

1. **`de/lexicon.test.js` is the safety net for shipped data.** It validates all 40 curated entries; `lexiconSample.test.js` validates real chunk rows. If either goes red, the new validation rejected data that shipped — that is a bug in the rules, not in the data.
2. **`mapEntry.test.js` lives under `scripts/`, not `src/`.** It imports `../../src/packs/validate.js`. It will import the German grammar the same way. That cross-boundary import is intended: it asserts the importer's output satisfies the German pack's contract.
3. **`ARTICLES` and `CEFR` have exactly one importer** — `src/packs/validate.test.js:216`. Verified: every other mention of "CEFR" in the repo is prose or an unrelated `DECK_GROUPS` string. `POS` stays and keeps its export.

  const g = pack.grammar;
  if (!g || typeof g !== 'object') fail('grammar is required');

  if (!Array.isArray(g.articles) || !g.articles.every(nonEmpty)) {
    fail('grammar.articles must be an array of non-empty strings');

  if (typeof g.articleRequiredForNouns !== 'boolean') {

  if (g.articles.length === 0 && g.articleRequiredForNouns) {

  }

  if (!g.auxiliaries || typeof g.auxiliaries !== 'object') {
    fail('grammar.auxiliaries must be an object');

  for (const [aux, third] of Object.entries(g.auxiliaries)) {
    if (!nonEmpty(third)) fail(`grammar.auxiliaries.${aux} must be a non-empty string`);

  if (!Array.isArray(g.personKeys) || g.personKeys.length === 0 || !g.personKeys.every(nonEmpty)) {

  if (!nonEmpty(g.displayPerson) || !g.personKeys.includes(g.displayPerson)) {
    fail('grammar.displayPerson must be one of grammar.personKeys');

  if (!g.labels || typeof g.labels !== 'object') fail('grammar.labels must be an object');
  for (const k of ['perfect', 'participle']) {
    if (!nonEmpty(g.labels[k])) fail(`grammar.labels.${k} must be a non-empty string`);

```js
// Formats a resolved card's (best-effort, nullable-fielded) verb block into
// compact display lines for the vocab card. Pure — each line appears only when
// its data exists. Order: the pack's display person, then the perfect (or a
// participle-only fallback when the auxiliary is unknown).
//
// The algorithm is the engine's; every value it reads comes from the pack.

/**
 * @param {object|null} verb
 * @param {{ auxiliaries: Record<string,string>, displayPerson: string, labels: { perfect: string, participle: string } }} grammar
 * @returns {{ label: string, value: string }[]}
 */
export function formatVerb(verb, grammar) {
  if (!verb || typeof verb !== 'object') return [];
  const lines = [];

  const person = grammar.displayPerson;
  if (verb.present?.[person]) {
    lines.push({ label: person, value: verb.present[person] });
  }

  if (verb.partizip2) {
    // An auxiliary the pack does not declare yields undefined and falls to the
    // participle line. The old rule guessed the haben form for anything that
    // was not 'sein'.
    const aux3sg = grammar.auxiliaries[verb.aux];
    if (aux3sg) {
      lines.push({ label: grammar.labels.perfect, value: `${aux3sg} ${verb.partizip2}` });
    } else {
      lines.push({ label: grammar.labels.participle, value: verb.partizip2 });
    }
  }

  return lines;
}
```

## Notes for the implementer

**Why the field names stay German.** `partizip2` is a slot a pack fills, not a German-only field. Renaming it would mean regenerating nine `public/lexicon/chunk-*.json` files (~2.3 MB) and reworking `parseWiktextract.js` / `mapEntry.js` / `filter.js` — a much larger phase with real risk to shipped content, for a naming improvement. Every pack brings its own importer anyway.

**Why no defaults on the new parameters.** Defaulting `grammar` to `activePack.grammar` would spare most of the test churn, but it drags the pack registry into two pure modules. Phases 1.2 and 1.3 both moved away from exactly that coupling.

**The one rule that catches a silent bug.** `displayPerson` must be in `personKeys`. Violate it and nothing throws — `verb.present[person]` is `undefined`, so the conjugation row simply never renders and the vocab card quietly loses a line. Same shape as Phase 1.3's level-key trap, where a casing mismatch interpolated the string `"undefined"` into a prompt.

**What is deliberately still German.** `resolve.js:8` composes `${article} ${de}`, wrong for suffixed-article languages. `POS` stays engine-owned, so a pack needing `particle` or `classifier` is rejected. And `src/lib/stats.js:23` holds a third level list, `LEVELS = ['a1','a2','b1']` — not grammar, so out of scope here, but the last hardcoded level list standing. All three are recorded in spec §6.
