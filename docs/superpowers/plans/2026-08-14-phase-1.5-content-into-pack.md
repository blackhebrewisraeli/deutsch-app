# Phase 1.5 — Content Into the Pack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Delete `src/data/`, landing its content as four focused modules in `src/packs/de/`, and move the last two pieces of German out of engine code — the chat greetings stranded in `ChatTab` and the article-position assumption in `resolve.js`.

**Architecture:** A mechanical four-way split first, keeping the suite green. Then three small behaviour-preserving moves: greetings nest inside their scenario, special letters become a flag on the alphabet entry, and `articlePosition` threads through the resolve chain as an explicit argument.

**Tech Stack:** React 18, Vite 5, Vitest + React Testing Library. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-14-phase-1.5-content-into-pack-design.md`

## Global Constraints

- **Move content verbatim.** Tasks 1–3 relocate data; they do not reword, reformat or "tidy" it. A changed German string is a content change smuggled into a move, and no test will catch it.
- **No component test may change.** `AlphabetTab.test.jsx`, `VocabTab.test.jsx` and every other component test must pass untouched. The rendered output is identical throughout. Test churn in `src/packs/` is expected (Task 1 splits a test file; Task 4 changes a signature).
- **Category C is out of scope.** Do not touch the ~25 German chrome/gamification strings (`Anfänger`, `Tagesziel erreicht!`, `WILLKOMMEN`, `DU`, `tippt`, `Alles gut!`, `Übersetzen`). They are enumerated in spec §6 and get their own spec.
- **Tests use `globals: false`** — every test file must `import { describe, it, expect } from 'vitest'`.
- **Never bypass `.husky/pre-commit`** (`lint-staged` + full `npm test`). `--no-verify` is forbidden.
- **Branch from up-to-date `main`; land via a non-draft PR targeting `main`.** CI only runs on PRs targeting `main`.

## Three facts that will confuse you

1. **`ChatTab` reads `intros[scenario]` twice** — once for `setMessages`, once inside a `setTimeout` for `speak(...)`. Both are in the same `useEffect` at `ChatTab.jsx:59-85`. Miss the second and the greeting is silent.
2. **`content.test.js` has two shared consts** — `SCENARIO_IDS` and `LEVELS` — declared once at the top and used across several `describe` blocks. When the file splits, each new test file needs its own copy of whichever it uses. They are test-local fixtures, not exports.
3. **`resolveAutoDeck` is the runtime path**, used by `VocabTab` for auto-decks resolved from the chunked lexicon. `resolveDecks` is the build-time path used by `de/index.js` for curated decks. Both call `resolveCard`, so both need grammar threaded — missing either leaves half the vocab cards composing their display form the old way.

## Notes for the implementer

**Why Task 1 is a pure move.** Splitting a file and changing its contents in
one commit makes the diff unreviewable — nobody can tell a relocated line from
an edited one. Tasks 2–4 change values only after the move has landed green.

**Why both resolve paths need grammar.** `resolveDecks` handles curated decks
at build time from `de/index.js`; `resolveAutoDeck` handles auto-decks at
runtime from `VocabTab`, resolving out of the chunked lexicon. They are
separate call chains that both bottom out in `resolveCard`. Threading only one
leaves half the vocab cards on the old composition, and no test would
necessarily catch it — which is why Step 4 of Task 5 greps rather than trusting
the suite.

**What must not change.** The ~25 category-C strings (spec §6) and
`src/lib/stats.js:23`'s `LEVELS`. Both are named limits carried forward, not
oversights. If you find yourself editing `gamification.js`, stop.
